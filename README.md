# PifPaf Creators

Внутренний кабинет блогеров: приватные аккаунты, список Reels, сохранённые показатели и серверная синхронизация Instagram через Apify.

## Быстрый запуск

```bash
cp .env.example .env
# Задайте ADMIN_PASSWORD и APIFY_TOKEN в .env
npm start
```

Откройте `http://localhost:3000`. При первом запуске создаётся файл `data/db.json` с администратором из `ADMIN_EMAIL` и `ADMIN_PASSWORD`. Каталог `data` специально исключён из Git: в нём находятся пользователи, хеши паролей, сессии, Reel и история метрик.

## Apify

Токен не попадает в браузер. Сервер отправляет ссылку Reel или ссылку Instagram-профиля выбранному actor в Apify, сохраняет результат и добавляет снимок метрик.

Минимальная настройка в `.env`:

```bash
APIFY_TOKEN=apify_api_...
APIFY_ACTOR=apify/instagram-scraper
SYNC_INTERVAL_MS=21600000
```

Что означают переменные:

- `APIFY_TOKEN` — обязательный серверный токен из Apify → Settings → Integrations. Он используется только в `server.js` и не встраивается в `app.js`.
- `APIFY_ACTOR` — actor для Instagram. По умолчанию используется `apify/instagram-scraper`; если вы выбрали другой actor, проверьте названия полей и при необходимости обновите `normalize` в `server.js`.
- `SYNC_INTERVAL_MS` — период фонового обновления уже сохранённых Reel. Например, 6 часов — `21600000`. При `0` фоновые обновления выключены; ручное обновление по кнопке `•••` у Reel остаётся доступным.

Чтобы не добавлять каждый Reel вручную, откройте «Интеграция», укажите `@handle` или `https://instagram.com/handle`, выберите лимит последних публикаций и нажмите «Подключить профиль и подтянуть рилсы». Сервер вызовет Apify по URL профиля, создаст недостающие Reel, обновит уже сохранённые и продолжит обновлять их по расписанию `SYNC_INTERVAL_MS`.

Apify может списывать usage за каждый запуск actor. Начните с небольшого лимита (например, 12), проверьте результат в кабинете и только потом увеличивайте лимит или частоту фоновой синхронизации.

## Production

На чистом Debian/Ubuntu с направленным DNS выполните:

```bash
sudo bash install.sh
```

Скрипт запросит домен, email сертификата, администратора и Apify token, создаст закрытый `.env`, systemd-сервис, Nginx reverse proxy и сертификат Let's Encrypt.

Установщик самостоятельно копирует приложение в `/opt/pifpaf-creators`. Не запускайте systemd-сервис прямо из `/root/...`: системный пользователь `www-data` не может зайти в домашнюю директорию root.

До запуска направьте DNS-запись домена на IP сервера — иначе Let's Encrypt не сможет выпустить сертификат. Ошибка Certbot `NXDOMAIN looking up A/AAAA` означает, что DNS-записи для домена нет или она ещё не распространилась. Скрипт проверяет DNS перед выпуском нового сертификата и останавливается с понятной подсказкой. После установки проверьте `https://ваш-домен/api/health`.

### Скрипт обновления

После получения новой версии проекта перейдите в её каталог на сервере и запустите:

```bash
sudo bash install.sh --update
```

Это неинтерактивный режим обновления: он берёт домен, порт, администратора, Apify token и интервал синхронизации из уже созданных `/opt/pifpaf-creators/.env` и Nginx-конфига, поэтому повторно вводить email, пароль и токены не нужно. Скрипт обновляет код, перезапускает сервис и ждёт ответа `/api/health`. Если приложение не поднялось, он выводит `journalctl -u pifpaf-creators` и состояние systemd-сервиса вместо короткой ошибки `curl: (7)`.

Каталог `/opt/pifpaf-creators/data/` не перезаписывается при установке или обновлении: в нём находятся пользователи, хеши паролей, сессии, Reel и история метрик. На первом запуске администратор создаётся строго из `ADMIN_EMAIL` и `ADMIN_PASSWORD` в `.env`; при изменении этих переменных установщик применит новые учётные данные к администратору после перезапуска. Перед обновлением всё равно сделайте резервную копию `data/`.

### QR-вход через Telegram

Установщик запрашивает параметры QR-авторизации Telegram: `TELEGRAM_API_ID`, `TELEGRAM_API_HASH` и список `TELEGRAM_ALLOWED_USER_IDS`. Первые два значения создайте в [Telegram API development tools](https://my.telegram.org/apps). В последний параметр внесите числовой ID каждого Telegram-аккаунта, которому разрешён вход, через запятую. Не оставляйте список разрешённых ID пустым: без него QR-вход отключён.

После установки на странице входа нажмите «Войти через Telegram» и отсканируйте QR-код в Telegram: **Настройки → Устройства → Подключить устройство**. Код действует две минуты. Сервис проверяет ID отсканировавшего аккаунта по списку разрешённых, поэтому сам по себе QR-код не даёт доступ любому пользователю Telegram.

Перед публичным запуском обязательно используйте длинный уникальный `ADMIN_PASSWORD`, настройте резервное копирование `data/` и ограничьте доступ к серверу.
